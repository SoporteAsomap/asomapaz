Preparacion del Servidor

3.1 Actualizar el sistema

# Conectarse al servidor via SSH
ssh usuario@IP_DEL_SERVIDOR

# Actualizar paquetes del sistema
sudo apt update && sudo apt upgrade -y

3.2 Instalar Docker

# Instalar dependencias
sudo apt install -y ca-certificates curl gnupg lsb-release

# Agregar clave GPG oficial de Docker
sudo mkdir -p /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | \
  sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg

# Agregar repositorio de Docker
echo \
  "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] \
  https://download.docker.com/linux/ubuntu $(lsb_release -cs) stable" | \
  sudo tee /etc/apt/sources.list.d/docker.list > /dev/null

# Instalar Docker Engine y Docker Compose
sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-compose-plugin

# Agregar tu usuario al grupo docker (evita usar sudo)
sudo usermod -aG docker $USER
newgrp docker

# Verificar instalacion
docker --version
docker compose version

3.3 Instalar Git

sudo apt install -y git
git --version

3.4 Configurar Firewall (UFW)

# Permitir SSH, HTTP y el puerto de la app
sudo ufw allow OpenSSH
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw allow 8080/tcp   # puerto de la app
sudo ufw enable
sudo ufw status

Configuracion del Codigo Fuente

4.1 Clonar el repositorio

# Ir a la carpeta donde se alojara la aplicacion
cd /opt
sudo mkdir asomap
sudo chown $USER:$USER asomap
cd asomap

# Clonar el repositorio (reemplaza la URL con la tuya)
git clone https://github.com/TU_USUARIO/asomap.git .

# Verificar que los directorios esten presentes
ls -la
# Debe mostrar: asomap-backend-jazzmin/  asomap-ui-main/  asomap/  docker-compose.yml

4.2 Configurar el archivo .env

Crea el archivo .env en la raiz del proyecto (/opt/asomap/.env):

# Crear el archivo .env
nano /opt/asomap/.env

Pega el siguiente contenido y ajusta los valores segun tu servidor:

# ============================================================
# BASE DE DATOS
# ============================================================
DB_USER=asomap_user
DB_PASS=TU_PASSWORD_SEGURO_AQUI      # CAMBIAR — usa uno fuerte
DB_NAME=asomap
DB_HOST=db
DB_PORT=5432
USE_DOCKER_DB=True

# ============================================================
# DJANGO
# ============================================================
DEBUG=False
SECRET_KEY=TU_SECRET_KEY_UNICO_AQUI   # CAMBIAR — genera uno nuevo

# ============================================================
# SERVIDOR — cambia 192.168.54.10 por la IP real del servidor
# ============================================================
SERVER_IP=192.168.54.10
SERVER_PORT=8080
SERVER_PROTOCOL=http

# Hosts permitidos
ALLOWED_HOSTS=127.0.0.1,0.0.0.0,192.168.54.10

# CORS
CORS_ALLOWED_ORIGINS=http://192.168.54.10:8080,http://localhost:8080

# CSRF
CSRF_TRUSTED_ORIGINS=http://192.168.54.10:8080,http://192.168.54.10

# ============================================================
# FRONTEND
# ============================================================
VITE_API_URL=http://192.168.54.10:8080
VITE_ENV=production
VITE_GOOGLE_MAPS_API_KEY=TU_GOOGLE_MAPS_KEY   # opcional

# ============================================================
# MEDIA y ESTATICOS
# ============================================================
MEDIA_ROOT=/app/media
STATIC_ROOT=/app/staticfiles
!
Importante: Genera una SECRET_KEY segura con el siguiente comando y usala en el .env:
python3 -c "import secrets; print(secrets.token_urlsafe(50))"

4.3 Proteger el archivo .env

# Solo el propietario puede leerlo
chmod 600 /opt/asomap/.env

Configuracion del Frontend (Build automatico con Docker)

v
No necesitas instalar Node.js ni Yarn en el servidor. El servicio frontend-build en Docker Compose compila el frontend automaticamente dentro de un contenedor y deja los archivos listos en un volumen compartido con Nginx.

Como funciona el flujo automatico

docker compose --profile prod up
↓
frontend-build (Node 18)
yarn install + yarn build
↓ copia /app/build → volumen frontend_build
nginx-prod espera a que frontend-build termine
(service_completed_successfully)
↓ monta volumen frontend_build
Nginx sirve los archivos estaticos

5.1 Verificar que VITE_API_URL esta en el .env

La URL de la API se pasa al build como argumento en tiempo de compilacion. Ya la configuraste en la seccion 4, pero verifica que este presente:

# Verificar la variable en el .env raiz
grep VITE_API_URL /opt/asomap/.env
# Debe mostrar: VITE_API_URL=http://192.168.54.10:8080
i
Vite bake la URL de la API dentro del bundle JavaScript en tiempo de build. Si cambias VITE_API_URL despues del despliegue, debes reconstruir la imagen del frontend con docker compose build frontend-build y reiniciar.

5.2 Reconstruir el frontend tras cambios

Si modificas el codigo del frontend o cambias VITE_API_URL:

# Reconstruir solo el frontend (Docker descarga las dependencias y compila)
docker compose build frontend-build

# Reiniciar para que nginx tome el nuevo build
docker compose --profile prod up -d --force-recreate frontend-build nginx-prod

Configuracion del Backend para Produccion

!
Accion requerida: El archivo start.sh actualmente usa python manage.py runserver que NO es apto para produccion. Debes cambiarlo a Gunicorn antes de hacer el despliegue.

6.1 Modificar start.sh para usar Gunicorn

Edita la ultima linea del archivo asomap-backend-jazzmin/start.sh:

# Abrir el archivo
nano /opt/asomap/asomap-backend-jazzmin/start.sh

# Cambiar la ULTIMA linea de:
exec python manage.py runserver 0.0.0.0:8000

# Por esta (Gunicorn con 3 workers):
exec gunicorn config.wsgi:application \
    --bind 0.0.0.0:8000 \
    --workers 3 \
    --timeout 120 \
    --access-logfile - \
    --error-logfile -

6.2 Verificar que Gunicorn esta en requirements.txt

# Verificar que gunicorn aparece en requirements.txt
grep gunicorn /opt/asomap/asomap-backend-jazzmin/requirements.txt

# Si NO aparece, agregarlo:
echo "gunicorn==21.2.0" >> /opt/asomap/asomap-backend-jazzmin/requirements.txt

6.3 Verificar MEDIA_ROOT en settings.py

El settings.py tiene MEDIA_ROOT = '/home/media' que no coincide con el volumen Docker. Confirma que el docker-compose.yml sobreescribe esta variable:

# En docker-compose.yml ya esta configurado como variable de entorno:
# - MEDIA_ROOT=/app/media
# Esto sobreescribe el valor del settings.py. No hay que cambiar nada mas.
i
El settings.py tiene CORS_ALLOW_ALL_ORIGINS = True y ALLOWED_HOSTS = ['*']. Esto es flexible pero menos seguro. En una red interna cerrada esta aceptable. Para produccion en internet publico, considera restringirlos via las variables de entorno del .env.

Despliegue con Docker Compose

7.1 Ir al directorio raiz del proyecto

cd /opt/asomap

7.2 Construir las imagenes Docker

# Construir todas las imagenes (primera vez tarda varios minutos)
docker compose build

# Si quieres ver el progreso detallado:
docker compose build --no-cache --progress=plain

7.3 Levantar los servicios en modo produccion

# Levantar con el perfil de produccion (nginx-prod en lugar de nginx+frontend-dev)
docker compose --profile prod up -d

# Verificar que los contenedores estan corriendo
docker compose ps

Debes ver algo como esto:

NAME                    IMAGE      STATUS                      PORTS
asomap_postgres         postgres   Up (healthy)                0.0.0.0:5433->5432/tcp
asomap_backend          asomap...  Up (healthy)                0.0.0.0:8000->8000/tcp
asomap_frontend_build   asomap...  Exited (0)                  # normal — termina al copiar el build
asomap_nginx_prod       nginx...   Up                          0.0.0.0:8080->80/tcp
i
Es normal que asomap_frontend_build aparezca como Exited (0). Ese contenedor solo existe para compilar el frontend y copiar los archivos al volumen. El codigo de salida 0 significa que termino exitosamente.

7.4 Ver los logs en tiempo real

# Todos los servicios
docker compose logs -f

# Solo el backend
docker compose logs -f backend

# Solo la base de datos
docker compose logs -f db
v
Cuando el backend este listo veras en los logs: Backend Django iniciado correctamente! y Servidor disponible en http://0.0.0.0:8000

7.5 Comandos utiles de Docker Compose

ComandoDescripcion

docker compose stopDetener todos los servicios
docker compose startIniciar servicios detenidos
docker compose restart backendReiniciar solo el backend

Configuracion de Dominio y SSL (HTTPS)

i
Esta seccion aplica cuando ASOMAP tenga un dominio registrado (ej: asomap.com) y el servidor sea accesible desde internet. El certificado SSL es gratuito con Let's Encrypt.

10.1 Paso 1 — Apuntar el dominio al servidor

En el panel del proveedor de dominio (GoDaddy, Namecheap, Cloudflare, etc.), crear los siguientes registros DNS:

TipoNombreValorTTL
A@IP_DEL_SERVIDOR (ej: 45.32.100.15)3600
AwwwIP_DEL_SERVIDOR (ej: 45.32.100.15)3600
!
Los cambios de DNS pueden tardar entre 15 minutos y 48 horas en propagarse. Verifica que el dominio apunta al servidor antes de continuar con Certbot.
# Verificar que el dominio ya apunta al servidor
ping asomap.com
# Debe mostrar la IP del servidor

10.2 Paso 2 — Actualizar el .env con el dominio

# Editar el .env en el servidor
nano /opt/asomap/.env

Cambiar estas variables:

SERVER_IP=asomap.com
SERVER_PORT=443
SERVER_PROTOCOL=https

ALLOWED_HOSTS=127.0.0.1,localhost,asomap.com,www.asomap.com
CORS_ALLOWED_ORIGINS=https://asomap.com,https://www.asomap.com
CSRF_TRUSTED_ORIGINS=https://asomap.com,https://www.asomap.com
VITE_API_URL=https://asomap.com

10.3 Paso 3 — Reconstruir el frontend con la nueva URL

La URL de la API queda grabada dentro del bundle de React en tiempo de build, por lo que hay que reconstruir:

# Reconstruir el frontend con la nueva VITE_API_URL
cd /opt/asomap
docker compose build frontend-build

# Reiniciar nginx y frontend-build para aplicar los cambios
docker compose --profile prod up -d --force-recreate frontend-build nginx-prod

10.4 Paso 4 — Instalar Certbot para SSL gratuito

# Instalar Nginx del sistema y Certbot (fuera de Docker)
sudo apt install -y nginx certbot python3-certbot-nginx

# Detener el Nginx de Docker para liberar el puerto 80
docker compose stop nginx-prod

10.5 Paso 5 — Obtener el certificado SSL

# Certbot obtiene el certificado y configura Nginx automaticamente
sudo certbot --nginx -d asomap.com -d www.asomap.com

# Verificar que la renovacion automatica funciona
sudo certbot renew --dry-run
v
Let's Encrypt renueva el certificado automaticamente cada 90 dias. No necesitas hacer nada manualmente.

10.6 Paso 6 — Configurar Nginx del sistema como proxy

# Crear archivo de configuracion para ASOMAP
sudo nano /etc/nginx/sites-available/asomap

Contenido del archivo:

server {
    listen 443 ssl;
    server_name asomap.com www.asomap.com;

    ssl_certificate     /etc/letsencrypt/live/asomap.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/asomap.com/privkey.pem;

    # Proxy hacia el contenedor Docker de Nginx
    location / {
        proxy_pass http://localhost:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}

# Redirigir HTTP a HTTPS automaticamente
server {
    listen 80;
    server_name asomap.com www.asomap.com;
    return 301 https://$host$request_uri;
}
# Activar la configuracion
sudo ln -s /etc/nginx/sites-available/asomap /etc/nginx/sites-enabled/
sudo nginx -t
sudo systemctl restart nginx

# Volver a levantar el contenedor Docker de Nginx
docker compose --profile prod up -d nginx-prod

10.7 Verificacion final con dominio

# Verificar HTTPS
curl -s -o /dev/null -w "%{http_code}" https://asomap.com/health/
# Debe responder: 200

# Verificar redireccion HTTP → HTTPS
curl -s -o /dev/null -w "%{http_code}" http://asomap.com/
# Debe responder: 301

Flujo con IP local

  • Sin certificado SSL
  • URL: http://192.168.1.50:8080
  • Solo accesible en la red interna
  • Puerto 8080 abierto en el firewall

Flujo con dominio publico

  • SSL gratuito con Let's Encrypt
  • URL: https://asomap.com
  • Accesible desde cualquier lugar
  • Puertos 80 y 443 abiertos

11.1 Ver logs

# Logs en tiempo real de todos los servicios
docker compose logs -f

# Ultimas 100 lineas del backend
docker compose logs --tail=100 backend

# Logs de errores del backend
docker compose logs backend 2>&1 | grep -i error

11.2 Monitorear recursos del sistema

# Ver consumo de CPU y RAM de los contenedores
docker stats

# Ver espacio en disco
df -h

11.3 Actualizar la aplicacion

# 1. Descargar cambios del repositorio
cd /opt/asomap
git pull origin main

# 2. Reconstruir solo el backend (si hubo cambios en Python/Django)
docker compose build backend
docker compose --profile prod up -d --force-recreate backend

# 3. Reconstruir el frontend (si hubo cambios en React o en VITE_API_URL)
docker compose build frontend-build
docker compose --profile prod up -d --force-recreate frontend-build nginx-prod

# 4. Reconstruir todo a la vez
docker compose --profile prod build
docker compose --profile prod up -d --force-recreate

11.4 Programar backups automaticos (crontab)

# Abrir el crontab del usuario
crontab -e

# Agregar esta linea para backup diario a las 2 AM
0 2 * * * cd /opt/asomap && docker compose exec -T db \
  pg_dump -U asomap_user asomap > /opt/backups/asomap_$(date +\%Y\%m\%d).sql
# Crear carpeta de backups
sudo mkdir -p /opt/backups
sudo chown $USER:$USER /opt/backups

11.5 Limpiar Docker periodicamente

# Limpiar imagenes y contenedores no utilizados
docker system prune -f

# Limpiar todo (CUIDADO: no elimina volumenes con datos)
docker system prune -a -f

Solucion de Problemas

ErrorCausa probableSolucion
Backend no inicia / health check falla PostgreSQL no esta listo o migraciones fallaron Ver logs: docker compose logs backend. Asegurarse que db este healthy antes.
Error 500 en la API Falta variable de entorno o migracion pendiente Revisar logs del backend. Ejecutar docker compose exec backend python manage.py migrate
Frontend muestra pantalla en blanco frontend-build fallo o VITE_API_URL incorrecta Ver logs: docker compose logs frontend-build. Verificar que VITE_API_URL esta en el .env. Reconstruir con docker compose build frontend-build.
nginx-prod no inicia (espera frontend-build) frontend-build termino con error (codigo distinto de 0) docker compose logs frontend-build para ver el error de compilacion. Corregir el codigo y reconstruir.
CORS error en el navegador CORS_ALLOWED_ORIGINS no incluye el origen del frontend Agregar la URL del frontend en CORS_ALLOWED_ORIGINS del .env y reiniciar.
Archivos de media no se ven MEDIA_ROOT no apunta al volumen correcto Verificar en .env: MEDIA_ROOT=/app/media. Revisar volumen media_data.
Puerto 8080 ocupado Otro proceso usa el puerto sudo lsof -i :8080 para ver que proceso lo usa. Detenerlo o cambiar el puerto en docker-compose.yml.
Container "Exited" inmediatamente Error en start.sh o configuracion docker compose logs backend para ver el error exacto.
No puedo conectar a la BD Credenciales incorrectas o contenedor de DB caido Verificar DB_USER, DB_PASS y DB_NAME en .env. docker compose ps para ver estado de db.
Admin panel no carga CSS collectstatic no se ejecuto docker compose exec backend python manage.py collectstatic --noinput
git pull falla: conflictos Cambios locales no commiteados git stash para guardar cambios temporalmente, luego git pull, luego git stash pop.

Checklist Final — Antes de ir a Produccion

  • El archivo .env esta creado con todos los valores correctos
  • DEBUG=False en el .env
  • SECRET_KEY es unica y segura (no la del repositorio)
  • DB_PASS tiene una contrasena fuerte
  • SERVER_IP apunta a la IP real del servidor
  • VITE_API_URL apunta a la URL correcta del servidor
  • El start.sh fue modificado para usar Gunicorn en lugar de runserver
  • docker compose --profile prod up -d levanta sin errores
  • docker compose logs frontend-build muestra "Frontend build copiado correctamente"
  • docker compose ps muestra db, backend y nginx-prod como Up (frontend-build como Exited 0)
  • El health check responde: curl http://SERVER_IP:8080/health/
  • El frontend carga correctamente en el navegador
  • El panel admin es accesible en /admin/
  • La contrasena del usuario admin fue cambiada
  • El firewall esta configurado (solo puertos necesarios abiertos)
  • Se configuro un cron para backups automaticos de la BD
  • Los logs no muestran errores criticos
